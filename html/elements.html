Every HTML element, demonstrated

A catalogue of the elements in the HTML living standard, grouped by what they are for. Each entry renders a working example, and the paragraph underneath says what the element actually does and when it earns its place.

Open this file directly in a browser, or serve the folder (npx serve / python -m http.server) so the audio, captions and iframe demos load without file:// restrictions. View source alongside the page — the markup is the lesson.

1 · Document skeleton

These elements cannot be demonstrated in place — there is exactly one of most of them per document, and this page is already using them. So the examples here are markup, not rendering.

<!DOCTYPE html> document type declaration

Markup

<!DOCTYPE html>
<html lang="en"> … </html>

Not an element at all — it is a declaration, and it must be the very first thing in the file. Its only job today is to switch the browser into standards mode. Omit it and you get quirks mode, where the browser emulates 1990s layout bugs on purpose and things like the box model change under you.

<html> root element

Markup

<html lang="en">
  <head> … </head>
  <body> … </body>
</html>

The root of the tree; everything else is a descendant. Always set lang — it tells screen readers which voice to use, drives hyphenation and the correct quote glyphs, and lets the browser offer translation.

<head> metadata container

Markup

<head>
  <meta charset="utf-8">
  <title>Page title</title>
  <link rel="stylesheet" href="app.css">
</head>

Holds information about the document rather than content to display: the title, character encoding, stylesheet and script references, and metadata for search engines and social previews. Nothing in here is rendered, with the single exception of <title>, which appears in the tab.

<title> document title

Markup

<title>Every HTML element, demonstrated</title>

The name of the page. It shows in the browser tab, is what a bookmark is named, is the blue headline in search results, and is the first thing a screen reader announces on load. Required in every document — one per page.

<meta> metadata void

Markup

<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="description" content="One sentence for search results.">
<meta property="og:image" content="/preview.png">

A catch-all for metadata that has no dedicated element. The three that matter on almost every page: charset (put it in the first 1024 bytes or the browser has to guess), viewport (without it a phone pretends to be a 980px desktop and shrinks everything), and description. The og: family drives link previews in chat apps and social feeds.

<link> external resource link void

Markup

<link rel="stylesheet" href="app.css">
<link rel="icon" href="/favicon.svg">
<link rel="canonical" href="https://example.com/page">
<link rel="preload" href="/font.woff2" as="font" crossorigin>

Declares a relationship between this document and an external resource. The rel attribute is what decides the meaning: load a stylesheet, name the favicon, point at the canonical URL, register a web app manifest, or hint the loader to preconnect and preload. One element, a dozen different jobs.

<style> embedded CSS

Markup

<style>
  body { font-family: system-ui; }
</style>

CSS written inline in the document instead of fetched via <link>. Handy for a single-file page like this one and for critical above-the-fold styles; a poor choice for a real site, because embedded CSS cannot be cached across pages.

<base> base URL void

Markup

<base href="https://example.com/docs/" target="_blank">

Sets the URL that every relative link and asset path on the page resolves against, and optionally a default target for all links. At most one per document. It is rare and easy to get wrong — it silently rewrites every relative URL, including ones you forgot about.

<body> document content

Markup

<body>
  <header> … </header>
  <main> … </main>
  <footer> … </footer>
</body>

Everything the user actually sees. One per document. It is also where the document-level events land — load, unload and friends fire here.

2 · Content sectioning

These carve the page into named regions. Visually most of them are just a <div>; the difference is that assistive technology exposes them as landmarks a user can jump between, so choosing the right one is a real accessibility decision rather than a style preference.

<header>

Pepper — food, fast

Introductory content for the page or for the nearest section: a logo, a title, a byline, a search box. A page can contain many — one for the site, and one inside each <article> — but only the top-level one becomes the banner landmark.

<nav>

Skeleton · Text · Forms

A block of major navigation links. Reserve it for the primary sets — main menu, in-page table of contents, breadcrumbs — not for every group of links on the page. If there is more than one, give each an aria-label so they can be told apart.

<main>

Markup — this page has exactly one, wrapping every section

<body>
  <header>…</header>
  <main>the content unique to this page</main>
  <footer>…</footer>
</body>

The dominant content of the document — what is left once the site header, navigation, sidebar and footer are stripped away. One per page, and it must not be nested inside the sectioning elements. It is the target of "skip to content" links and the fastest way for a screen reader user to get past your navigation.

<section>

Delivery areas

We deliver within 5km of the city centre.

A thematic grouping of content, almost always with a heading of its own. The test is simple: if you would list it in the document's outline, it is a <section>; if you are only wrapping things to hang CSS on, it is a <div>.

<article>

Why the box model bites

Padding used to be added to width. Then border-box happened.

Posted 9 Sep 2026

A self-contained composition that would still make sense if you lifted it out and put it somewhere else: a blog post, a product card, a comment, a forum reply. The syndication test is the useful one — if it could sensibly appear alone in an RSS reader, it is an article.

<aside>

Aside: the browser's default styles come from a built-in stylesheet you can read in DevTools.

Content that is tangential to what surrounds it — a pull quote, a glossary box, a related links panel, an ad. The bar is that removing it should not damage the meaning of the main content.

<footer>

© 2026 · Back to top

Closing content for its nearest section: authorship, copyright, related links, the date. Like <header> it can appear many times — inside each article as well as once for the page — and only the top-level one is the contentinfo landmark.

<h1>…<h6> section headings

h1 — the page's one true title

h2 — a major section

h3 — a subsection

h4 — deeper still

h5 — rarely needed
h6 — the floor

Six ranks of heading that build the document outline. Screen reader users navigate by jumping heading to heading, so the rule that matters is never skip a level to get a smaller font — pick the rank that reflects the structure and set the size in CSS. One <h1> per page is the safe convention.

<hgroup> heading + tagline

Loom

Shirts that outlive the trend

Ties a single heading to its subheading or tagline so the extra line does not appear in the outline as content of its own. Contains exactly one h1–h6 plus one or more <p>.

<search> search landmark

A wrapper for search and filtering controls. It is one of the newest elements, and it exists so you can stop writing role="search" by hand — it maps to that landmark natively.

<address>

Written by Minh.
Reach me at someone@example.com.

Contact details for the author of the nearest <article> or of the page as a whole. Despite the name it is not for postal addresses in general — a delivery address in a shipping form is just a <p>. Browsers render it italic by default.

3 · Text blocks

Block-level content: paragraphs, lists, quotes, preformatted text.

<p> paragraph

A paragraph is the default unit of prose.

Browsers add vertical margin between them automatically, which is why two paragraphs look separated without any CSS at all.

The workhorse block of running text. Its closing tag is optional in HTML — a new block element implicitly ends it — but a <p> cannot contain another block element, so nesting a <div> inside one silently splits it in the parsed DOM.

<hr> thematic break void

The end of one topic.

The start of another.

A shift in topic — a scene change in a story, the end of one part of a document. It started life as a decorative "horizontal rule", which is where the name comes from, but it is defined semantically now. If you only want a line, use a CSS border.

<pre> preformatted text

select id, name
  from users
 where active = true;

Text whose whitespace and line breaks are significant, rendered in a monospace font exactly as written. Everything between the tags is preserved, including the newline right after <pre> — which is why the opening tag is usually jammed against the content. For source code, nest a <code> inside it.

<blockquote>

The Web does not just connect machines, it connects people.

— Tim Berners-Lee

An extended quotation from another source, set off as its own block. The cite attribute takes a URL for the source — machines can read it, but browsers do not display it, so put a visible attribution in a <footer> with <cite>.

<ul> unordered list

  • HTML gives it meaning
  • CSS gives it looks
  • JavaScript gives it behaviour

A list whose order does not carry meaning — shuffle the items and nothing is lost. Its only permitted children are <li>, <script> and <template>.

<ol> ordered list

  1. Parse HTML into the DOM
  2. Parse CSS into the CSSOM
  3. Combine them into a render tree

A list where sequence is part of the meaning: steps, rankings, instructions. Attributes worth knowing — start to begin at another number (as above), reversed to count down, and type to switch to letters or roman numerals.

<li> list item

  1. an item forced to number 10
  2. the next one continues from there

One entry in a <ul>, <ol> or <menu>. Inside an ordered list, value overrides its number and every following item counts on from that.

<menu> toolbar list

    •

    Semantically identical to <ul> — the spec defines it that way — but intended for a list of commands or a toolbar. An earlier version of the spec tried to make it build real context menus; that was dropped, and what remains is a naming choice.

    <dl> <dt> <dd> description list

    DOM
    The live object tree the browser builds from your HTML.
    CSSOM
    The same idea for stylesheets.

    Name/value pairs: <dt> is the term, <dd> the description. Good for glossaries, metadata tables and FAQ pairs. One term may have several descriptions and vice versa — the grouping is by adjacency, not by nesting.

    <figure> <figcaption>

    Self-contained referenced content — an image, a diagram, a code listing, a table — bundled with its caption. The point is the association: the <figcaption> is programmatically tied to the content, and the whole unit can be moved elsewhere in the document without breaking the prose that refers to it.

    <div> generic container

    column
    column

    A block container with no meaning whatsoever. That is the feature: it is the right choice when you need a box purely for layout or styling. It is the wrong choice when a meaningful element exists, and reaching for it by default is how pages end up as a stack of anonymous boxes that assistive technology cannot navigate.

    4 · Inline semantics

    Elements that mark up a phrase inside a line of text. Several pairs look identical on screen and differ only in meaning — that difference is what screen readers, search engines and translation tools act on.

    <a> anchor

    An in-page link, an external one, and a mailto: link. A download link

    A hyperlink — the element the entire Web is built on. href can point at another page, a fragment on this one, an email address, a phone number or a file. target="_blank" opens a new tab and should be paired with rel="noopener noreferrer", and download saves the resource instead of navigating to it.

    <span> generic inline container

    Temperature: 38°C

    The inline twin of <div>: no meaning, exists so you can attach styles, a class or a lang attribute to a run of text. Use it only when no semantic element fits.

    <br> line break void

    Roses are red,
    violets are blue,
    this line break is meaningful.

    A line break that is part of the content — addresses, poetry, song lyrics. It is not a spacing tool: if you are stacking two <br> to push things apart, you want CSS margin instead.

    <wbr> word break opportunity void

    https://example.com/a/very/long/path/that/needs/somewhere/to/break

    Marks a spot where the browser may break a line if it needs to, and does nothing otherwise. Made for long URLs and compound words that would otherwise overflow their container. Unlike a hyphen, it leaves no visible character behind.

    <em> emphasis

    I said you should read the spec.

    Stress emphasis — the word a speaker would lean on, which can change the meaning of a sentence. Renders italic and screen readers may alter their intonation. Nest it for heavier stress.

    <strong> strong importance

    Warning: this deletes the branch permanently.

    Marks content as important, serious or urgent — not merely loud. Renders bold. The contrast with <em> is importance versus vocal stress.

    <i> idiomatic text

    The word terra is Latin, and HMS Beagle is a ship's name.

    Text set apart from the surrounding prose for a reason with no more specific element: a foreign phrase, a technical term, a taxonomic name, a ship's name, a thought. Historically "italic", now defined by that idiomatic role — reach for <em> when you actually mean emphasis.

    <b> bring attention to

    The following ingredients are keywords in the product listing.

    Draws attention to a span of text without implying extra importance — product names in a review, the lead-in of an article. It is the fallback when nothing more meaningful applies; if the text is genuinely important, use <strong>.

    <u> unarticulated annotation

    He wrote recieve on the form.

    A non-textual annotation, most usefully a spelling error or a proper name in Chinese. It is genuinely risky to use, because underlined text reads as a link — style it differently, as above, or pick another element.

    <s> no longer accurate

    $79.00 $49.00

    Content that is no longer relevant or accurate — an old price, a cancelled item. For edits to a document that are being tracked, use <del> instead: that one says who removed it and when.

    <small> side comment

    Subscribe for $5/month. Cancel any time. Terms apply.

    Small print: legal disclaimers, licensing notes, attributions. It carries the meaning of "fine print", and reducing the font size is the browser's default rendering of that — not the reason to use it.

    <mark> highlight

    Results for "cascade": the cascade resolves conflicting declarations.

    Text highlighted for reference in the current context — search-result hits, the line an explanation is talking about. The relevance comes from the reader's activity, not from the document itself.

    <abbr> abbreviation

    Styling is done with CSS. (hover it)

    An abbreviation or acronym, with the expansion in title. Browsers show that as a tooltip on hover, which touch devices cannot do — so spell the term out in the prose the first time as well, and treat the element as machine-readable backup.

    <cite> title of a work

    I keep going back to The Design of Everyday Things.

    The title of a creative work — a book, film, paper, song, exhibition. It refers to the work, not the person; a name goes in plain text or a <span>. Renders italic.

    <q> inline quotation

    She said the hard part is naming things and moved on.

    A short quotation that sits inside a sentence. The browser adds the quotation marks for you — and picks the right ones for the language, so a lang="fr" ancestor produces guillemets. Do not type your own quotes around it.

    <dfn> definition

    A DOM is the live tree a browser builds from HTML.

    Marks the one place in the document where a term is defined, as opposed to merely used. The nearest ancestor paragraph or section is taken to contain the definition.

    <code>

    Call array.at(-1) to read the last item.

    A fragment of computer code — a function name, a filename, a snippet. Renders monospace. For a multi-line block, wrap it in <pre>, since <code> alone does not preserve whitespace.

    <kbd> keyboard input

    Press Ctrl + K to open the palette.

    Input the user is expected to type or a key they should press. Nesting it inside <samp> means "input echoed back by the system"; the default rendering is plain monospace, so the key-cap look above is CSS.

    <samp> sample output

    The command prints 2 files changed, 41 insertions(+).

    Output from a program or system — the counterpart to <kbd>. Useful in documentation to distinguish what you type from what the machine says back.

    <var> variable

    The area is w × h.

    A variable name in a mathematical expression or a programming context, including placeholders in prose. Renders italic.

    <sub> <sup> subscript / superscript

    H2O · E = mc2 · 4th · Kelvin1

    Typographical subscript and superscript where the position carries meaning: chemical formulas, exponents, ordinal suffixes, footnote markers. Not for stylistic raising or lowering of text — CSS vertical-align handles that.

    <time>

    Published this morning, and the doors open at 7pm.

    A date, time or duration, with a machine-readable version in datetime while the visible text stays human. This is what lets calendars offer "add to calendar" and search engines show event times.

    <data>

    Three hundred and ninety-eight subscribers.

    The general version of <time>: human-readable text with a machine-readable value attached. Product IDs, quantities, prices — anything a script or a scraper should read differently from how a person reads it.

    <bdi> bidirectional isolate

    Without isolation: user إيان: 3 posts With isolation: user إيان: 3 posts

    Isolates a run of text whose direction is unknown — typically a username or other user-supplied string — so that right-to-left content cannot reorder the punctuation and numbers around it. Essential anywhere you interpolate untrusted names into a sentence.

    <bdo> bidirectional override

    This text is forced right-to-left.

    Forces a direction rather than letting the algorithm decide. dir is required. It is a blunt instrument used mainly to demonstrate or repair bidi behaviour — for ordinary multilingual content, set dir on a normal element instead.

    <ruby> <rt> <rp> ruby annotations

    漢 (kan) 字 (ji)

    Small pronunciation or meaning annotations printed above East Asian characters. <rt> holds the annotation; <rp> holds fallback parentheses that only appear in browsers with no ruby support, so the text degrades to 漢(kan)字(ji) instead of becoming unreadable.

    5 · Edits

    Two elements for showing that a document changed, and when.

    <ins> inserted text

    The meeting is at 2pm 4pm.

    Content added to the document since a previous version. datetime records when the edit happened and cite links to an explanation. Renders underlined by default.

    <del> deleted text

    This paragraph was removed in the September revision.

    Content removed from the document, with the same datetime and cite attributes. Its cousin <s> means "no longer accurate"; <del> specifically means "edited out", which is why it is the right one in changelogs and tracked revisions.

    6 · Embedded content

    Elements that pull something else into the page — an image, another document, a media stream, a drawing surface.

    <img> image void

    Embeds an image. alt is required — descriptive text for anyone who cannot see it, and an empty alt="" for purely decorative images so screen readers skip them. Always set width and height: the browser reserves the space before the file arrives, which stops the page from jumping as it loads.

    <picture> <source>

    Resize the window past 700px — the crop changes.

    Lets the browser choose between several image files. Each <source> offers a candidate with conditions — a media query for art direction, or a type for modern formats like AVIF with a JPEG fallback — and the first match wins. The <img> at the end is mandatory: it is the fallback and the element that actually renders.

    <audio>

    Embeds sound with a native player. Without controls it renders nothing at all, which is a common first surprise. Browsers block autoplay with sound until the user has interacted with the page — a deliberate policy, not a bug.

    <video> <track>

    The repo ships no video file, so this player is pointed at the same short audio clip — the poster stays up while it plays. Press play with captions on: everything about the element except the moving pictures is real. Turn captions on via the player's CC menu.

    Embeds video with a native player. Multiple <source> children let you offer several codecs and the browser picks the first it can play; anything after them is fallback content for browsers that support none. <track> attaches a WebVTT file of captions, subtitles or chapters, and poster is the still shown before playback.

    <iframe> inline frame

    Embeds an entire separate browsing context — another whole document with its own DOM, styles and scripts. That isolation is the point, and it is what makes third-party embeds (maps, videos, payment forms) safe to include. sandbox tightens the box further by removing capabilities unless you opt each one back in, and title is required for accessibility.

    <object>

    A generic external resource, handled by the browser or a plugin according to type. Its distinguishing feature is that its child content is fallback, shown when the resource fails. It dates from the plugin era and is largely superseded by <img>, <video> and <iframe>.

    <embed> void

    The same idea as <object> but void, so it has no fallback content at all. It exists mostly for historical compatibility; with plugins gone from the Web there is rarely a reason to pick it over a purpose-built element.

    <canvas>

    A bar chart drawn with the canvas API.

    A blank bitmap you draw on from JavaScript, in 2D or through WebGL/WebGPU. The element itself is only a rectangle of pixels — nothing you paint exists in the DOM, so it is invisible to screen readers and search engines. Put fallback content between the tags and think hard before using it for anything text-based.

    <svg> inline vector graphics

    Vector graphics written directly in the markup, in their own XML namespace. Unlike <canvas> every shape is a real DOM node, so it can be styled with CSS, animated, and given aria labels. This is the right way to ship icons and diagrams that must stay crisp at any size.

    <math> MathML

    a= -b2c

    Mathematical notation, again in its own namespace, with elements for fractions, roots, scripts and matrices. Core MathML is supported in all current browsers now, so formulas can be real accessible markup rather than an image or a JavaScript renderer.

    <map> <area> image map

    Hover the sun or the big hill — the cursor changes.

    Divides a single image into clickable regions. <map> is referenced by an image's usemap, and each <area> defines a shape with pixel coordinates and its own link and alt. Those coordinates do not scale with responsive images, which is why image maps are now rare — overlaying positioned links is usually better.

    7 · Tables

    For tabular data — two dimensions of related values — and nothing else. Everything below appears in one worked example first, then element by element.

    <table> and its whole family

    Bundle sizes, September 2026
    BundlerCold buildOutput
    esbuild0.9s142 KB
    Rollup3.4s138 KB
    webpack7.1s151 KB
    Measured on the same project, three runs each.

    The container for tabular data. Everything else in this group is a child of it, and the order the spec requires is caption, colgroup, thead, tbody, tfoot. Tables were abused for page layout for a decade; that is what <div> and CSS grid are for now.

    <caption>

    Markup — rendered above the table in the example above

    <table>
  <caption>Bundle sizes, September 2026</caption>
  …

    The table's title. It must be the first child, and it is announced when a screen reader user lands on the table — which makes it the cheapest accessibility win a data table has. Move it visually with CSS caption-side.

    <colgroup> <col>

    Markup

    <colgroup>
  <col>
  <col span="2" style="background: #fdfdfe;">
</colgroup>

    Styles or attributes applied down whole columns without touching every cell. Columns cut across the row-based structure of a table, so this is the only way to reach them; only a few properties (background, border, width, visibility) actually apply.

    <thead> <tbody> <tfoot>

    Markup

    <thead><tr><th scope="col">Bundler</th>…</tr></thead>
<tbody><tr><th scope="row">esbuild</th>…</tr></tbody>
<tfoot><tr><td colspan="3">Notes</td></tr></tfoot>

    Row groups: the header, the data, and the summary row. Splitting them out lets the browser repeat the header when a long table is printed across pages, and lets you scroll the body under a fixed header. <tbody> is inserted automatically by the parser even when you leave it out.

    <tr> <th> <td>

    Cell typeMeaning
    tha header for its row or column
    tdan ordinary data cell

    <tr> is a row; <th> and <td> are the cells inside it. The attribute that matters is scope on every <th> — it tells assistive technology whether a header labels its column or its row, which is what lets a screen reader announce "esbuild, cold build, 0.9s" instead of a bare number. colspan and rowspan merge cells.

    8 · Forms

    How a page collects input. Forms are where HTML gives you the most for free — validation, keyboard behaviour, mobile keyboards, autofill — and where hand-rolled replacements most often throw all of it away.

    <form>

    Submitting empty triggers the browser's own validation message.

    Groups controls and defines where their values go: action is the URL, method is get (values in the query string) or post (values in the body). It also turns on native validation and lets Enter submit. Forms cannot be nested.

    <label>

    The visible name of a control, tied to it either by for pointing at the control's id or by wrapping it. This is not optional decoration: it is what a screen reader announces, and it makes the label itself a click target, which matters a lot for small checkboxes on touch screens.

    <input> the many-headed one void

    many of many hiddenrenders nothing, and cannot be labelled — it just carries a value through submission

    One element with more than twenty behaviours, chosen by type. Picking the right type is worth real effort: it selects the mobile keyboard, enables free validation (email, url), provides native pickers for dates and colours, and drives autofill. Constraints come from required, min, max, pattern and maxlength — no JavaScript needed.

    <button>

    A clickable control. The trap is type: inside a form it defaults to submit, so a button meant to open a menu will reload the page unless you write type="button". Prefer it to a clickable <div> — you get focus, Enter and Space, and screen reader semantics for free.

    <select> <optgroup> <option>

    A dropdown of predefined choices. <option> is one choice — its value is submitted while its text is displayed — and <optgroup> puts them under non-selectable headings. Add multiple to turn the dropdown into a scrolling multi-select list.

    <datalist>

    Suggestions for a text input, wired up with list pointing at the datalist's id. Unlike <select> the user can still type anything — this is autocomplete, not a constraint.

    <textarea>

    Multi-line free text. Its value is the content between the tags, not a value attribute, so whitespace and the first newline matter. rows sets the visible height, and CSS resize controls whether the user may drag it larger.

    <fieldset> <legend>

    Delivery speed

    Groups related controls under a shared caption. It is the correct way to label a set of radio buttons, because each radio's own label only names one option — the <legend> names the question. Setting disabled on the fieldset disables everything inside it at once.

    <output>

    + = 42

    The result of a calculation or user action. It is an ARIA live region by default, so updating its text makes a screen reader announce the new value — which is exactly what you want for a running total, and what a plain <span> would not do.

    <progress>

    70% working… The second has no value — an indeterminate task.

    How far along a task is: a file upload, an install step. Omit value and it renders as an indeterminate spinner or barber pole. It is about completion over time — not a gauge.

    <meter>

    A scalar measurement inside a known range — disk usage, a score, a temperature. The low, high and optimum attributes let the browser colour it green, amber or red on its own, as the second bar shows. Use <progress> for tasks and <meter> for gauges.

    9 · Interactive

    Two widgets the browser implements for you — both replacing a pile of JavaScript that used to be written by hand on every project.

    <details> <summary>

    Why is this collapsed by default?

    Because <details> is closed unless it has the open attribute. Add name="group" to several of them and they behave as an accordion where only one can be open at a time.

    And this one has open

    So it starts expanded.

    A native disclosure widget: <summary> is the always-visible label and everything else shows when it is expanded. Keyboard support, ARIA state and in-page find all work without a line of script. It is also the honest way to do FAQs and "show more" panels.

    <dialog>

    A real modal dialog

    Focus is trapped inside, the page behind is inert, and Esc closes it — all from the browser. The dimmed backdrop is the ::backdrop pseudo-element.

    A modal or non-modal dialog. Opened with showModal() from JavaScript, it gets focus trapping, Esc-to-close, inert background content and a styleable backdrop for free — the things hand-built modals almost always get wrong. A <form method="dialog"> inside closes it and reports which button was used.

    10 · Scripting & templates

    Elements that carry behaviour, or markup that is deliberately not rendered.

    <script>

    Markup

    <script src="app.js" defer></script>
<script type="module">import { init } from './app.js';</script>
<script type="application/json" id="data">{"ok": true}</script>

    Embeds or references executable code. Parsing stops while a plain script loads and runs, which is why defer (run after parsing, in order) and async (run as soon as it arrives) exist. type="module" gives you ES modules and is deferred automatically; an unknown type is not executed at all, which is the standard way to smuggle JSON into a page.

    <noscript>

    Nothing appears above unless you turn JavaScript off and reload.

    Content shown only when scripting is unavailable — a fallback message, or a <noscript> image for analytics. With JavaScript enabled its contents are parsed but never rendered.

    <template>

      The template above holds one <li>; the script cloned it three times into this list.

      Markup that is parsed but inert: not rendered, images not fetched, scripts not run. You clone its .content from JavaScript to stamp out repeated structures. It is how you keep a component's HTML in HTML instead of in a template string.

      <slot>

      Light DOM goes in This sentence was written in the page, but rendered inside the component's shadow DOM.

      A placeholder inside a shadow DOM where the component's own children get projected. A named slot takes elements with a matching slot attribute; the unnamed one takes everything else; the content between the tags is the default when nothing is passed. This is how web components accept children.
