Comments

Text the engine skips. Comments explain why code does something — the code itself already says what it does.

Single line

Everything after // to the end of the line is ignored.

Multi line

Everything between /* and */ is ignored, however many lines it spans.

Commenting code out

The everyday use: disabling a line while you test something else.

Comments at the end of a line

Doc comments

A /** … */ block written above a function is picked up by editors, which show it when you hover the function name. This is the JSDoc convention.

Comments that earn their place

  • Bad: i++; // increment i — repeats the code.
  • Good: a note about a constraint you cannot see in the code (an API quirk, a business rule, why the obvious approach failed).
  • Good: a TODO: or FIXME: marker — most editors index them.
  • If a comment is needed to explain what a block does, a well-named function usually removes the need for the comment.
