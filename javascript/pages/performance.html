Performance

Measure before you optimise. Almost all of it comes down to three things: do less work, touch the DOM less, and do not block the main thread.

Measuring

DOM writes are the expensive part

Each insertion into the live document can cause layout work. Build off-document, then insert once.

Reading layout forces a reflow

Cache repeated work

Throttle and debounce

Events like input, scroll and resize fire far faster than you need to react.

Do not block the main thread

What actually matters

  1. Network: fewer and smaller files beat every micro-optimisation.
  2. Rendering: batch DOM changes, avoid layout thrashing.
  3. Algorithms: a Set lookup instead of a nested loop turns O(n²) into O(n).
  4. Only then: loop style, and it almost never matters.
