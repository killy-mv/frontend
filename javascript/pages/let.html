Let

let declares a variable that lives only inside the block it was declared in. That one difference from var fixes several long-standing traps.

Block scope

A block is any pair of curly braces. A let declared inside one does not exist outside it.

var ignores blocks

The same code with var has only one variable, and the block overwrites it.

The loop counter classic

With var the three callbacks share one counter, which has reached 3 by the time they run. With let each iteration gets a fresh binding.

Redeclaring

let refuses to declare the same name twice in the same scope — which is almost always a mistake you wanted to be told about.

The temporal dead zone

var variables read as undefined before their declaration line. let variables throw instead — the gap between entering the scope and reaching the declaration is called the temporal dead zone.

let and the global object

A top-level var becomes a property of window. let does not.
